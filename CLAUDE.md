# Сайт консалтинговой фирмы по закупкам — контекст проекта

## Что это
Корпоративный сайт (Главная, О нас, Услуги + 3 специализации, Аналитика, Контакты, скрытые Примеры
проектов) со своей CMS и DMS. Все тексты пока заглушки, фирма условно называется «Меридиан».
Язык сайта — русский.

## Стек и хостинг
- **Cloudflare Worker** `procurement-site` (аккаунт imakanovr), адрес https://procurement-site.imakanovr.workers.dev.
- **Хранилище** — один Durable Object `Store` с SQLite (`src/store.js`). D1/R2/KV не используются:
  у коннектора Cloudflare в Claude нет на них прав, а DO доступен с правом Workers Scripts.
  Файлы (картинки, документы) лежат в SQLite кусками по 1 МБ.
- **Статика** (`dist/assets`, собирается `build.mjs`) отдаётся Cloudflare без запуска Worker:
  админка, SVG-заглушки, а также `_data/seed.json`, `_data/schemas.json`, `_data/site.css`, `_data/site.js`.
  Worker и DO читают их через binding `ASSETS`.
- Сборка — esbuild (`node build.mjs`), Wrangler запускает её сам (`[build]` в wrangler.toml).
  Фреймворков нет: шаблоны — тегированные строки `h```, админка — ванильный JS.

## Важные решения (не ломать)
- **`h``` экранирует все подстановки**; сырой HTML — только через `raw()` (результат `markdown()`, иконки).
  Новые шаблоны пишите так же.
- **`attrs()` пропускает false/null/undefined, но оставляет пустую строку** — нужен `alt=""` у декоративных картинок.
- **Ошибки из DO передаются через RPC только сообщением**, поэтому `AppError` кодирует статус в тексте
  (`§404§…`), а `parseAppError()` в воркере его разбирает.
- **Кеш снимка контента:** 10 с в памяти изолята (+ Cache API на собственном домене). После записи
  из админки вызывается `invalidateSnapshot()`. Правки на сайте видны через 10–20 с.
- **Производительность:** CSS и JS сайта встроены в HTML, внешних шрифтов нет, картинки — WebP с srcset
  (размеры готовит админка в браузере). Не добавлять render-blocking ресурсов и тяжёлых библиотек:
  Lighthouse сейчас 100/100/100 (perf/a11y/best practices).
- **GA4 грузится только после согласия в cookie-баннере** (`src/client/site.js`).
- **Индексация выключена** (`settings.indexing = false`, noindex + `Disallow: /`) до запуска с реальным
  контентом и доменом.
- Новое поле контента = схема в `src/schemas.js` + значение в `src/seed.js` + вывод в `src/render/pages.js`.
  `npm test` проверяет, что seed соответствует схемам.
- В исходниках не должно быть последовательности `*/` вне комментариев (в регэкспах пишите `[*]/`).
  Это нужно для деплоя через API (код передаётся внутри комментария).

## Деплой
- Обычный путь: `npx wrangler deploy` или Cloudflare Workers Builds из GitHub (push → деплой).
- Если Wrangler/токена нет, деплой через MCP Cloudflare (`execute`):
  1) сессия загрузки статики (`assets-upload-session`) через MCP;
  2) загрузка файлов статики из песочницы напрямую на `api.cloudflare.com/.../workers/assets/upload`
     по JWT сессии (без токена аккаунта);
  3) PUT скрипта через MCP с `assets.jwt` = токен завершения. Код передаётся частями с проверкой SHA-256.
  Если менялась только статика, берите развёрнутый скрипт через `GET …/content/v2`, а не передавайте заново.
  При PUT указывайте `keep_bindings: ["secret_text"]`, иначе пропадёт `SETUP_TOKEN`; блок `migrations`
  повторно не отправляйте (v1 уже применена).
- Секреты: `SETUP_TOKEN` (задан), `RESEND_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TURNSTILE_SECRET`, `IP_SALT` (необязательные).

## Тесты
- `npm test` — юнит-тесты (markdown, DMS-нумерация, экранирование, соответствие seed схемам).
- `node test/e2e.mjs <url> <email> <пароль>` — Chromium: форма заявки, вход, правка главной, загрузка
  картинки, документ в DMS, все разделы админки, мобильная вёрстка. Делает скриншоты в `docs/img`.
  **На живом сайте тест меняет контент** — после него верните подзаголовок главной, картинку специализации
  и удалите тестовый документ.
- `node test/smoke.mjs <url>` — HTTP-проверка маршрутов и заголовков.
- `node test/screens.mjs <url> [пути]` — скриншоты на трёх ширинах и проверка горизонтального скролла.

## Языки
- ru (без префикса), kk (`/kk`), en (`/en`). Перевод — наложение (`overlay()` в `src/lib/util.js`): пустая строка и пустой список = русский текст, числа/флажки всегда русские, списки по индексу.
- Хранится в `docs` с ключами `kk:page:home`, `en:settings`, `kk:e:<id записи>`; стартовые переводы — `src/seed-i18n.js` (для записей ключ `тип:slug` или `hero:<название>`).
- Внутренние ссылки получают префикс пост-обработкой HTML в `layout()`. Новый жёстко прописанный текст в шаблоне нужно выносить в `settings.ui` (иначе он останется русским).
- Деплой через MCP большого бандла: считайте построчный патч относительно развёрнутой версии (код GET `…/content/v2` проверяется по SHA-256) и применяйте его в `execute`.
